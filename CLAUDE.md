# AzurCalc

Static catalog of every Azur Lane ship (888), its gear (~580 items) and Augment Modules, with
effective stats, DPS/AA/ASW estimates, an equipment optimizer and skill interactions.
Live at https://azurcalculator.ilph-creation.party (Cloudflare Workers static assets).

The full history of decisions, measurements and rejected approaches is in
[docs/NOTES.md](docs/NOTES.md). It is long: search it for the section named below before
touching the matching area, do not read it whole.

## Layout

- `index.html`, `app.js` (all app logic), `pixel.js` (dithered pixel-art gradients and header
  field), `style.css`. Plain HTML/CSS/vanilla JS, no framework.
- Five tabs, routed by `location.hash` (pushState throws on `file://`): Port (ship grid and
  modal), Depot (equipment grid + item detail), Augments, Targets (boss table; picking one sets
  the same `targetBoss` as the modal's menu, via `setTargetBoss`), Fleet (3 vanguard + 3 main,
  per-ship and fleet figures, synergies; kept in localStorage). All but Port load their data
  scripts on first visit. Code: "Views" section at the end of `app.js`.
- `data/*.js` is the only copy of the data (the `.json` twins were deleted on 2026-10-28, nothing
  read them): each file is `const X_DATA = <JSON.stringify(data, null, 2)>;`. Keep that
  pretty-printed form, never minify in the source tree. A Node script reads one with
  `vm.runInNewContext(src.replace(/^const (\w+) =/, "this.$1 ="), ctx)`. Globals: `SHIPS_DATA`,
  `EQUIPMENT_DATA`, `DEFAULT_EQUIPMENT_DATA`, `AUGMENTS_DATA`, `BOSSES_DATA`.
- `data/bosses.js` (212 end-game bosses: armour, hull, level, hit/eva/luck, `siren`, `timeLimit`) is generated by
  `node scripts/import-bosses.js` from mrlar.dev's `maps.json`; re-run it after a new event.
  `node scripts/import-aux-effects.js` rewrites the `effects` field of Auxiliary items in
  `data/equipment.js` from the game's buff/skill tables (AzurLaneData), linked through
  mrlar.dev's `equipments.json`; re-run it after a game update. It walks the buff chain the item
  attaches and accepts only known shapes and argument keys: extend `Walker.terminal`, never add
  a rule by item name.
  Game data from datamine sites is fair game, a site's own work is not: Regal
  (azur-lane-regal.suchiguma.com) is a tier list whose ratings, texts and damage figures are its
  authors' own (robots.txt `use=reference`), so it is a reference, never a data source.
- `data/skill-timing.js` (when each skill's effect is active, from the game's buff tables) is
  generated by `node scripts/import-skill-timing.js`; re-run after a game update. See "Buff
  uptime v1" in the notes.
- `data/focus.js` (face position in each painting, for centring the modal and the wide retrofit
  card icons) is generated by `scripts/focus-points.py` (Python + OpenCV 4, see its header);
  re-run it after adding paintings. See "Centring images on the character" in the notes.
- The source must keep working from `file://` (no server): that is why data is loaded as
  classic scripts and not `fetch`ed.
- `Site web/` (wiki pages saved by the user) and `programming rules/` are git-ignored
  reference material. See "Data provenance" in the notes before re-sourcing any data.

## Build and deploy

- `npm ci && npm run build` writes `dist/` (minified JS/CSS with source maps, WebP thumbnails,
  CSS inlined into `index.html`, CSP hash filled into `_headers`, `?v=` content hashes on
  scripts because the zone caches JS for 4h). Cloudflare serves `dist/` only.
- `_headers` is the security policy (strict CSP, no `unsafe-inline`). The app has no inline
  script, inline `style=`, `on*` handler, `eval` or network request: keep it that way. Details:
  "Deployment security" in the notes. Never use `toDataURL`/`getImageData` output in the page
  (LibreWolf fingerprinting protection randomizes it): see "ILPH theme".

## Rules that are easy to break

- Interaction and stat-bonus parsing favours precision over recall: when unsure, exclude.
  Read "Known precision guards in `computeInteractions`" and "Known data quality issues in
  `statBonuses`" first. Fix the root cause in general, then re-check the full 888-ship set.
- Narrow per-skill fixes exist on purpose where no safe general rule was found (e.g.
  `mergeUlrichProsaicListSentence`): do not generalise them.
- Do not retry gif resizing for the barrage hover delay (measured worse).
- Theme: JetBrains Mono for text, Silkscreen for short uppercase labels only, no
  `border-radius` except the Augment socket, no smooth gradients (go through `pixel.js`),
  AzurCalc's blue palette, not the hub's orange.
- Comments: why, not how, 1-2 sentences max ("Commenting standard" in the notes).

## Testing

`npm run check` loads the real page in headless Chromium and runs every ship through stats,
combat metrics, Optimize (2 levels x 2 rarity caps x every target x no boss or one boss per
armour) and the modal, failing on
errors, NaN, illegal or over-cap picks, or a target metric Optimize lowered. On this machine
(Fedora, Chromium is a Flatpak):
`CHROME="flatpak run io.github.ungoogled_software.ungoogled_chromium" npm run check`.
`--dump-dom` works here, unlike the old Windows/Edge workflow described in the notes.

## Open work

The user's direction (2026-10-28): numbers and strategy like the tier-list sites, but computed
here from game data - each ship's utility, potential uptime, and a chosen boss to optimise
gear and ships against, with easy navigation. Done so far: DPS per armour class, and the
Target boss menu (armour drives Optimize; boss hit/eva/luck drive eHP and crit), and skill
"DMG Dealt" bonuses restricted to armour classes only (`ARMOR_ONLY_TARGET_RE`: Alvitr, Achilles
retrofit, Gangut augment...), applied in the matching DPS column and against a picked boss.
Harbin (torpedoes only), Fleuret ("that enemy's Armor Type") and Z47 ("those ... enemies") are
excluded on purpose. Hull-only bonuses ("to enemy BBs", `HULL_TARGET_TERMS`) apply when the
picked boss has that hull (`hull` in data/bosses.js; "Carriers" and mixed lists like "DDs and
transport ships" are skipped). Siren-targeted bonuses ("to Sirens", or a nation list including Sirens) apply against a boss
with `siren: true`; other nation-targeted bonuses are still skipped (bosses carry no other
nationality). Operation Siren-only skill text ("[Operation Siren]", "humanoid Siren fleets or
Boss fleets") applies only against an "OpSi Arbiter" boss (`OPSI_CLAUSE_RE`). Optimize's per-slot
greedy limit was fixed on the user's request (2026-10-28, `refineWeaponPicks`, see "Whole-ship
weapon refinement" in the notes). Next:
- Utility and uptime per ship (heals, shields, fleet buffs, barrage/buff time on field): not
  started. Source found: AzurLaneTools/AzurLaneData (`EN/GameCfg/skill.json`, `buff.json`,
  `EN/ShareCfg/skill_data_template.json`; last updated 2026-05) and AzurLaneTools/
  AzurLaneLuaScripts (`EN/gamecfg/skill|buff/*.lua`, updated daily): structured triggers,
  per-level durations, cooldowns, effects. Ship skill icon ids (`Skill_20200.png`) are NOT game
  skill ids; link ships through the game's ship template instead. Proposed v1, awaiting the
  user's go-ahead and 3-4 reference ships: uptime line under each skill in the modal, then
  utility tags, then a catalog filter by utility.
- **Optimize and auxiliaries (diagnosed 2026-10-28, user wants it fixed next)**. Measured over
  every ship (auto goal, UR cap): CL gets Repair Toolkit + HP AA Radar ~165 times, DD Repair
  Toolkit + Type 93 ~250, Improved Hydraulic Rudder only 18 times, Autoloader never. Causes:
  1. The ship's RLD stat is ignored: DPS uses catalog fire rates (RLD 100 baseline) and no
     goal weighs `reload`. Wiki (Damage Calculations, Guns/Torpedoes): ReloadTime =
     WeaponReloadTime x sqrt(200 / (CurrentReload + 100)) + VolleyTime + AbsoluteCooldown.
     Aircraft and AA guns have their own formulas: read them in the same page first.
  2. Auxiliary passives are ignored (only `statBonus` is scored): Super Heavy Shell crit +8%,
     Type 1 AP crit DMG +25%, Rudder's evade proc, Anti-Torpedo Bulge -30% torpedo DMG. Two
     name-keyed hacks in `optimizeEquipment` (Admiralty Fire Control Table, Super Heavy Shell
     +1 score) stand in. mrlar.dev `equipments.json` gives each aux its game skill ids
     (Super Heavy Shell -> 6210); the effects are in the AzurLaneData skill/buff tables above.
  Agreed order: (1) RLD into gun/torpedo DPS + weights - **done 2026-10-28**, see "Live Reload
  in DPS" in the notes (aircraft/AA/ASW reload still at the catalog's RLD 100); (2) import aux
  effects from game data, delete the name hacks - **done 2026-10-28**, see "Auxiliary effects
  from game data"; (3) evade procs and damage reduction in eHP - **done 2026-10-28**, see
  "Auxiliary survival effects in eHP". Skill Evasion Rate / DMG Taken buffs stay out of eHP
  until their uptime is modelled (they reach +40% for a few seconds).
- Barrages take crit and general/targeted DMG Dealt like every bullet (client
  `battleformulas.lua`, see "Barrages take crit and DMG Dealt" in the notes); "Main Gun" bonuses
  stay on the main gun. AzurLaneLuaScripts `EN/mod/battle/data/battleformulas.lua` is the source
  for any further damage-formula question.

- Equipment-aware stats (HP/DPS/AA/ASW panel, rarity cap, Optimize): largely built, see
  "Unresolved / explicitly deferred".
- Team composition (Fleet tab): v1 done 2026-10-28, see "Fleet tab v1" in the notes. Its
  synergies are listed, not applied to the figures: that waits on buff uptime, next. Agreed
  design in the same notes section: uptime per skill from the game's tables, over 60 s or the
  picked boss's `timeLimit`, shown under each skill, applied as expected value.
